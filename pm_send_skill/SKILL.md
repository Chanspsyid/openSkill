# PM 飞书发送

## 前置条件

- `lark-cli` 已安装并授权；未就绪时引导用户使用 `$feishu_installCli_skill`。
- `workspace.yaml` 里 `feishu.profile` 非空时，所有 lark-cli 命令必须带 `--profile`。
- 只发送工作区内已定稿的文件（用户在 `pm_brief_skill` / `pm_delegate_skill` 流程中明确确认过的版本）；用户要求发送草稿时，先提醒这是草稿并再次确认。

## 输出规则（安全纪律）

- **绝不自动发送**。每次发送前必须向用户展示：接收人（人/群/文档位置）+ 发送方式 + 内容预览（长内容展示开头与结构），用户明确同意后才执行。
- 一次确认只对应一次发送；给多个对象发送要逐个确认，不允许「一次确认、批量群发」。
- 老板版只能发给老板，下属版只能发给下属——发送前核对文件名里的受众后缀与接收人是否匹配，不匹配必须拦下来向用户确认。
- 调用 lark-cli 前先用 `--help` 确认消息 / 文档模块的实际子命令和参数，不要凭记忆拼命令。
- 发送失败（scope 不足、找不到接收人）时，把原始报错给用户，提示可用 `$feishu_installCli_skill` 补授权；不要反复重试。
- 发送成功后，在源文件 frontmatter 追加发送记录：`sent: [{to: 接收人, via: doc|message, at: 时间}]`，避免重复发送时无据可查。

## 发送方式

按内容长度和用途建议方式，最终由用户定：

1. **飞书文档 + 消息发链接**（默认建议）：周报及以上、委派/招人材料。用 lark-cli 创建文档写入内容，再把链接连同一句摘要发给接收人。可追溯、好归档。
2. **直接发消息**：日报、简短同步。正文直接作为消息发送。
3. **只创建文档不发消息**：用户想自己转发时。

## 接收人管理

- 接收人优先从 `workspace.yaml` 读取（boss / team / reports)；首次给某人发送时，引导用户确认其飞书标识（open_id / 邮箱 / 群），并把映射写入 `workspace.yaml` 的 `feishu.recipients`（新增段，格式 `{名字: {id_type, id}}`）。
- 找不到映射时向用户要，不要猜测接收人。

## 典型流程

```text
用户：把这份周报老板版发给老板
1. 定位文件，确认是定稿（非 draft 后缀、经过确认流程）
2. 核对受众后缀 boss 与接收人「老板」匹配
3. 从 workspace.yaml 读老板的飞书标识；没有则先补录
4. 展示：接收人 + 方式（建议文档+链接）+ 内容预览 → 等用户确认
5. lark-cli 创建文档、发送消息
6. 回写 sent 记录，报告结果和文档链接
```
