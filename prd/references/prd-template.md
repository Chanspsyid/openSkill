# PRD 模版（逐节写法）

标题格式：`【状态】需求名`。需求名要一句话能看懂做什么，动词开头或"对象：动作"结构，如"新端：题目加载时长"。

各章节的用途、写法和示例如下。`（可选）`章节在不适用时整节删除，不要留空壳。

---

## # 需求背景

**回答"为什么是现在、为什么值得做"。** 3-6 条 bullet，每条一个理由，按说服力排序：

- 问题现状 + 数据证据，链接到数据来源（自测记录、反馈帖、数据看板）
  - 例：`加载时长普遍在 4-8s，部分低配 PAD 甚至在 14s 左右（链接）`
- 问题为什么重要：对用户/业务的传导链
  - 例：`加载过久让孩子走神、影响学习效果，最终体现在校内考试表现`
- 外部约束：上级要求的标准、业务承诺、竞对动作
- 时间节点：`秋季课节点：8.20 下载，9.3 解锁`

写法要点：证据链接就地引用；没有数据支撑的判断标 `==待补充：需要 xx 数据==`。

## # 需求目标

**回答"做到什么程度算成功"。** 包含四层，按需取用：

1. **交付承诺**：发布节点 + 交付形态（`在秋季课节点前提审并发布版本，并支持策略热更`）
2. **量化指标 + 优先级排序**：多目标冲突时显式写出取舍
   - 例：`产研优先级：进关卡时长不超过 5 秒 > 设备适配率不小于 95%`
   - 指标分层：`P0 场景：95% 推荐设备 <5s，90% 推荐设备 <3s`；`低配设备：上线观察`
3. **动作目标**：本期要完成的动作（`完成埋点 + 常态化回收数据`）
4. **产品思路**（可选）：从问题到方案的推导链，用缩进树表达分支判断，被否掉的路径注明原因
   - 例：
     ```
     - ✅ 确认：进题不临时下载
       - 能否提前完成加载渲染？=预加载，时机=进入上一个组件，风险=性能压力+不适用场景——==端侧执行==
         - 如果强制 loading 过场 1.5s，能否把有感时长控制在 3s 内？——==端侧执行==
           - 【本期不做，后续观察】极限时长>Xs 的设备，提供"知识回顾"过场
     ```

## # 技术调研（可选）

**回答"技术上行不行、代价多大"。** 涉及技术不确定性时才写：

- 可行性验证结论 + 证据链接（体验包、调研视频、POC 记录）
- 产能与排期约束（谁在做什么、什么时候能接）
- 候选优化思路清单及其状态

## # 需求方案

**文档主体。** 开头先给两样东西：

- 关键名词定义，用引用块置顶。指标类需求必须先定义测量口径：
  > **对用户有感加载时长的定义**：从用户点击题目入口，到题目素材加载完毕、且可正常交互
- 核心链路流程图（mermaid flowchart），标出关键分支和状态流转

### ## 功能方案

按优先级组织功能块，每块结构：

- `【P0】功能名`
  - **通用逻辑**：一段定义 + bullet 展开规则细节
  - **适用范围**：平台/科目/场景/对象范围逐项列出
  - **触发策略**：分场景写（不同场景触发时机不同就分开写）
  - **特殊情况**：边界 case 清单，逐条确认，已确认的打 `✅`，未确认的标 `==高亮==`
    - 例：`✅ 进入场景后第一个对象就是题目组件——需支持跨场景预加载`
- **上下游兼容**：本需求改动对上下游系统/旧数据/进行中流程的影响及兼容方案（跨系统需求必写）
- **兜底逻辑**：降级策略、失败重试、不满足前提条件时的行为
- **场景覆盖表格**：场景多时用表格穷举 `场景 | 情况 | 覆盖比例 | 配置要求 | 支持特性`

### ## 埋点方案（如涉及数据回收）

- **### 核心埋点**：定义成功指标的起点/终点事件。必须写清事件由谁触发（用户行为还是系统行为），这决定指标口径
- **### 过程埋点**：链路中间状态事件，用于归因分析
- **### 公共属性**：设备/网络/用户/课程等公共维度字段

每个事件写：事件名（含技术命名，如 `U3D_activate_preload_start`）、触发时机、字段清单（字段名/含义/单位）。不确定端上有没有现成事件，直接写疑问：`U3D 开始下载：有无事件？`

### ## 测试设备 / 验收（可选）

测试范围、设备清单、验收标准。未盘点就写 `待盘点`。

## # 信源线索

**让接手的人能追溯一切。** 三块：

- **历史方案**：相关旧文档/旧方案链接
- **本次需求**：讨论群、相关文档、原型、项目管理平台（meego/JIRA）链接、上级需求文档
- **相关人员**：业务/产品/各端研发的分工点名，未确认的人标 `==？==`
